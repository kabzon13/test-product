# Observability: что есть, что показывает, на что реагировать

## Из чего состоит

| Компонент         | Роль                                                                         |
| ----------------- | ---------------------------------------------------------------------------- |
| **Grafana**       | единый экран: дашборды, логи, алерты                                         |
| **Prometheus**    | хранит метрики (retention 15 дней)                                           |
| **Loki**          | хранит логи (retention 7 дней)                                               |
| **Alloy**         | агент-сборщик: логи из Docker → Loki, скрейп метрик → Prometheus, приём OTLP |
| node-exporter     | метрики сервера (CPU, RAM, диск)                                             |
| cAdvisor          | метрики контейнеров                                                          |
| postgres-exporter | метрики PostgreSQL                                                           |

Всё настроено файлами в `infra/observability/` (provisioning) — руками в UI ничего
не настраивается, любая правка = правка файла + git.

## Как открыть

- **Локально**: `make observability` → http://localhost:3001, логин `admin`,
  пароль — `GRAFANA_ADMIN_PASSWORD` из `.env`
- **Прод/стейджинг**: Grafana наружу не смотрит.
  `ssh -N -L 3001:localhost:3001 deploy@<reserved-ip>` → http://localhost:3001

## Дашборды: что смотреть и когда волноваться

### API — первый экран при любой проблеме

| Панель               | Что это                              | Тревога, если                                           |
| -------------------- | ------------------------------------ | ------------------------------------------------------- |
| RPS                  | запросов в секунду                   | резкий обвал к нулю (сайт лёг) или всплеск (атака/цикл) |
| Latency p50/p95/p99  | скорость ответов: медиана и «хвосты» | p95 > 1s стабильно                                      |
| 4xx / 5xx            | ошибки клиента / сервера             | любой устойчивый рост 5xx                               |
| Активные запросы     | сколько обрабатывается прямо сейчас  | растёт и не спадает — запросы зависают                  |
| RPS/p95 по маршрутам | кто именно грузит/тормозит           | один маршрут выбивается из общей картины                |

### Node.js — здоровье процесса API

| Панель         | Что это                            | Тревога, если                             |
| -------------- | ---------------------------------- | ----------------------------------------- |
| Heap           | память JS                          | «пила» растёт от деплоя к деплою — утечка |
| Event loop lag | заторможенность процесса           | p99 > 0.1s — CPU-bound код блокирует всё  |
| GC time/s      | время на сборку мусора             | постоянно высокое — памяти мало           |
| CPU / RSS      | процессор и полная память процесса | упирается в лимиты контейнера             |

### PostgreSQL

| Панель          | Что это                | Тревога, если                           |
| --------------- | ---------------------- | --------------------------------------- |
| Соединения      | открытые коннекты      | подползает к лимиту тарифа БД           |
| Транзакции/с    | нагрузка               | rollback растёт — ошибки в запросах     |
| Блокировки      | кто кого ждёт          | долгие блокировки = зависшие транзакции |
| Размер БД       | рост данных            | внезапный скачок                        |
| Cache hit ratio | доля ответов из памяти | < 0.95 — базе не хватает памяти         |

### Host & Docker — сервер целиком

CPU, RAM, диск, сеть, память по контейнерам, рестарты. Тревога: диск > 85%
(алерт есть), контейнер рестартует по кругу, память одного контейнера растёт без конца.

Локальный нюанс: на macOS (Docker Desktop) панели «Диск» и «по контейнерам»
могут быть пустыми — в проде на Ubuntu работают полностью.

### Logs — все логи всех контейнеров

- Что собирается: **stdout каждого контейнера** (api, web, worker, caddy, postgres, …).
  Приложения пишут JSON (pino), поэтому по полям можно фильтровать.
- Уровни pino — числа: 20 debug · **30 info · 40 warn · 50 error** · 60 fatal.
- Фильтры сверху: service (контейнер), level, requestId, userId.
- **Главный приём**: у каждой записи api есть `requestId` — он кликабелен.
  Клик = все логи этого запроса от начала до конца. Это заменяет трейсинг
  для типового случая.
- Панель «Ошибки по контейнерам» внизу — быстрый ответ «кто сыпет ошибками».

### Billing (Stripe)

Запросы к `/billing/*`, ошибки вебхуков, stripe-события в логах.
Тревога: растут 4xx/5xx на `/billing/webhook` — Stripe шлёт, а мы не принимаем
(он будет ретраить и в конце концов отключит endpoint).

## Алерты: на что реагировать

Все правила — `infra/observability/grafana/provisioning/alerting/rules.yaml`.
Канал: `ALERT_CHANNEL` = telegram или email. **По каждому алерту есть раздел
«что делать» в [troubleshooting.md](troubleshooting.md)** — алерт присылает ссылку.

| Алерт                    | Условие                 |
| ------------------------ | ----------------------- |
| API недоступен           | up == 0 дольше 2 мин    |
| Web-контейнер не запущен | не виден cAdvisor 2 мин |
| Много 5xx                | > 0.5 rps ошибок 5 мин  |
| p95 latency              | > 1s дольше 5 мин       |
| Диск                     | заполнен > 85%          |
| PostgreSQL недоступен    | pg_up == 0              |
| Цикл рестартов           | > 3 рестартов за 15 мин |
| Сертификат               | истекает < 14 дней      |

Отдельно от Grafana живёт **pull-uptime**: cron на сервере пингует healthchecks.io.
Если сервер умер целиком — Grafana умерла вместе с ним, а healthchecks заметит тишину
и поднимет тревогу. Это последний рубеж.

## Tempo (трейсинг)

Выключен, пока не задан `OTEL_EXPORTER_OTLP_ENDPOINT`. Включать, когда появятся
внешние вызовы или worker — см. [modules/tempo.md](modules/tempo.md).

## Порядок разбора инцидента

1. Дашборд **API** — что и когда сломалось
2. **Logs** → level=50 за тот же период → клик по requestId → вся цепочка
3. Совпало с деплоем → rollback, разбор потом
4. Полный алгоритм: [troubleshooting.md](troubleshooting.md)
