# Rollback

## Автоматический

Деплой сам откатывается на предыдущий SHA, если упали миграции, `/health`
или smoke-тест. История SHA хранится на сервере в `/opt/app/releases.log`.

## Ручной

GitHub Actions → workflow **rollback** → Run workflow:

1. окружение (staging | production)
2. SHA, на который откатиться (см. историю коммитов main или `releases.log`)

Что происходит: тот же путь, что деплой, но с указанным SHA. Образы уже лежат
в GHCR — пересборки нет, откат занимает минуты.

## Схема БД

Миграции expand/contract — откат кода не требует отката схемы.
Если миграция всё же несовместима со старым кодом, это ошибка проектирования
миграции: чинить вперёд (fix-forward), а не откатывать схему.

## Проверка после отката

- `make smoke ENV=<env>`
- Grafana: дашборд API без 5xx
- `git log <sha>` — что именно теперь работает в проде
